# PDF草案比較アプリ — Streamlit配備用

PDFの複数バージョンを配備アプリの実行環境内で統計処理により比較し、段落対応、変更箇所、トピック、Watch、メモを管理するStreamlitアプリです。このフォルダは、GitHub経由でStreamlit Community Cloudへ配備するためのコピーです。

## 同梱物

- `streamlit_app.py` — アプリ本体。起動時に `documents/` 内の3文書を読み込みます。
- `documents/` — 比較用のPDFサンプル。
- `training_data_seed.json` — 手動分類の初期教師データとユーザー定義トピック。
- `requirements.txt` — Pythonライブラリ一覧。
- `COP31_PDF_comparison_app_spec.md` — 詳細な仕様書。
- `README_app_reference.md` — 元プロジェクトの基本操作説明。

## 初期文書と初期学習データ

初期文書は、COP31 2026-11-16版、COP31 2026-11-19版、CMA8 cover decision annotated版の3本です。元プロジェクトの保存データにはPDFが4本ありましたが、比較画面で表示対象になっていたこの3本を配備用に含めました。非表示だったもう1本のCMA8 PDFは含めていません。

初期トピック分類は、元プロジェクトの保存済みユーザー訂正から、上記3文書に属する **22件の教師例** と **12段落の手動タグ指定** を収録しています。15個のユーザー定義トピック（推奨14タグと `principles`）も同梱しました。別文書に属する分類例は含めていません。教師データは `training_data_seed.json` にあり、新しい利用者セッションの開始時にアプリへ読み込まれます。

## 仕様の概要

- 1つの基準版の段落順に沿って、最大3つの比較版を横に並べます（同時比較は最大4文書）。
- PDFの段落番号は本文の先頭に表示しますが、段落番号自体は差分判定・差分ハイライトの対象にしません。
- 自動対応付けは本文の類似度による候補です。新設文言、削除、統合、移動を見つけ、必要に応じて対応先や配置順を手で修正できます。
- 自動トピック分析ではNMFで話題を発見します。ユーザー定義モードでは、同梱する手動分類例を使い、TF-IDFとロジスティック回帰または類似度で段落を分類します。分類は候補・参考値で、交渉上の判断を代替しません。
- トピックは複数付与できます。トピック名・説明、分類例、手動指定を編集できます。
- 比較画面に検索、トピック絞り込み、変更行のみ、章立て、段落番号ジャンプ、Watch表示、Watch追加／解除、蛍光ペン、メモ編集などがあります。
- `(a)`, `(b)`, `(c)` など小文字アルファベットの小段落ラベルは表示時に改行します。
- 検索語はオレンジ背景、手動蛍光ペンは黄色で表示します。
- 「メモ」は利用者が入力する自由記述です。自動翻訳はしません。メモが空の段落では空欄表示を出しません。
- 比較HTMLとプロジェクトZIPを出力できます。プロジェクトZIPにはPDF、段落抽出結果、トピック教師データ、Watch、メモ、手動配置など、その時点のセッション情報が含まれます。
- サイドバー上部に作業画面を配置します。PDFの追加・分析設定、プロジェクトの読込・保存は、必要なときだけ開く折りたたみ欄にまとめています。
- プロジェクトZIPまたは対応JSONを読み込んで、PDFと作業状態を復元できます。未保存の変更がある状態でページを閉じると、対応ブラウザーでは確認ダイアログが表示されます。

### UIの設計方針

サイドバーでは、繰り返し使う「比較」「トピックと学習」「Watch付箋」「メモ」「出力・保存」を最初に表示し、比較時の検索や段落ジャンプをその下に置いています。頻度の低いPDF読込・分析条件・プロジェクト入出力は折りたたみました。これは、作業状況を見せること、利用者に選択肢を思い出させず見つけられるようにすること、関係の薄い操作を前面に並べすぎないことを重視した配置です。[Nielsen Norman Groupのユーザビリティ・ヒューリスティック](https://www.nngroup.com/articles/ten-usability-heuristics/)を参考にしています。

## 基本的な使い方

### 比較する

1. URLを開くと、同梱の3文書が自動で読み込まれ、トピック分類が実行されます。
2. 上部の文書選択で基準版と比較版を選びます。基準版の段落順が比較の軸になります。文書の表示列は比較画面で個別に隠せます。
3. 左サイドバーの「比較」から検索、トピック絞り込み、章立て表示などを設定します。
4. Para番号を入力して「一番左の版のParaへ移動」を押すと、現在表示されている一番左の列の該当番号へ移動します。検索・トピック絞り込みで隠れている段落も、ジャンプ時には表示します。
5. 変更箇所は色で示されます。段落が統合・移動・新設された可能性もラベルで表示します。自動対応付けに迷いがあれば、手動配置の画面で修正します。

### PDFを追加する

1. サイドバーのPDF追加欄からファイルを選び、「PDFを読み込む」を押します。
2. 初期3文書を使う場合、同時比較の上限4文書までなので、追加できるのは1文書です。
3. 別の文書セットを使う場合は「全データをクリア」を押してからPDFをアップロードします。クリア後は、固定サンプルも再読込されません。
4. テキスト層のあるPDFが対象です。スキャン画像PDFはOCRを事前に行ってください。

### トピックと学習データを確認する

1. 左側の「トピックと学習」を開きます。初期状態ではユーザー定義の15トピックと、同梱の22教師例が読み込まれています。
2. 各段落に割り当てられたタグを確認し、必要なら複数の正しいタグを選んで訂正を保存します。
3. 新しい訂正例はそのセッション内の分類に使われます。ロジスティック回帰は対象トピックに正例と負例があり、教師例が4件以上ある場合に使います。それ以外は正例との類似度を参考値として表示します。
4. トピック名の変更や新規トピックの追加も可能です。分類を変えた後は「トピック分類を更新」を押します。

### Watchとメモを使う

- 比較画面で段落全体のWatchを追加・解除できます。「Watch操作」でそのボタンを表示・非表示にします。「Watchを表示」では付箋内容の表示を切り替えます。
- 文言の一部だけをWatchに登録するときは「Watch付箋」画面を使います。優先度、注記、タグを付けられます。
- メモは比較画面または「メモ」画面で入力します。英文の日本語訳を記録する場合もこの欄を使います。
- 検索語はオレンジ、蛍光ペンの語句は黄色になります。手動の蛍光ペンは原文に存在する語句・文を指定して保存します。

### 保存・出力する

- 「出力・保存」から現在の比較HTML、PDF込みHTMLパッケージ、プロジェクトZIPをダウンロードします。
- ZIPまたはJSONのプロジェクトファイルは、サイドバーの「プロジェクトを開く／保存」を開き、ファイルを選んで「プロジェクトを読み込む」を押します。復元すると保存時のPDF・分類訂正・Watch・メモ・配置設定が戻ります。
- HTMLに入力済みメモは表示されます。空のメモ欄や「元PDFの該当ページ」リンクは比較段落に出しません。
- 配備版ではサーバー上の共通自動保存を無効にしています。サイドバーまたは「出力・保存」からプロジェクトZIPをダウンロードしてください。未保存の編集はサイドバーにも表示します。
- 編集後にタブやページを閉じようとすると、未保存の場合はブラウザーの確認ダイアログが出ます。ダイアログからページに戻り、プロジェクトを保存できます。

## GitHubとStreamlit Community Cloudへの配備

1. この `streamlit_deploy` フォルダを展開します。
2. 中身全体をGitHubの新規リポジトリへ登録します。`documents/` のPDFもリポジトリに含まれます。
3. Streamlit Community CloudでGitHubアカウントを連携し、対象リポジトリ、ブランチ、アプリファイル `streamlit_app.py` を選んでDeployします。
4. 配備URLからアプリを開きます。コードを更新した場合はGitHubへpushすると、配備アプリに反映されます。

詳しい手順は[Streamlit公式の配備ガイド](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy)を参照してください。

## 配備・データ共有上の注意

- GitHubリポジトリを公開にすると、同梱PDFと教師データのJSONも公開されます。今回は公開済み資料を同梱する前提です。公開アプリも誰でもアクセス可能になり、検索エンジンに登録される設定があります。必要に応じてアプリやリポジトリを非公開にしてください。
- 追加でアップロードしたPDFは利用者のブラウザーからStreamlitサーバーへ送られて処理されます。公開アプリで他の人が使う場合、利用者がアップロードするPDFはそのサーバー上で処理されます。
- ブラウザー接続ごとに別々のセッションが作られます。利用者間のメモ、Watch、訂正例は自動共有されません。
- 同梱する教師データは各新規セッションの初期データです。その後の訂正はそのセッション内に保持され、共同の教師データへ自動反映されません。変更を引き継ぐ場合はプロジェクトZIPを受け渡すか、教師データ更新をGitHubへ反映します。
- 閉じるときの確認はブラウザー標準のダイアログです。文面をアプリから指定できず、特にモバイルではブラウザーが表示しない場合があります。そのため、画面内にも未保存状態と保存ボタンを常時確認できるようにしています。[beforeunloadのブラウザー制約](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)
- ブラウザーは、利用者がページを操作した後にだけ終了確認を出す場合があります。確認が出た場合は「このページにとどまる」を選び、サイドバーの「プロジェクトZIPを保存」からダウンロードしてください。アプリは閉じる操作を検知して自動保存するものではありません。
- 同時編集、ユーザー別アカウント・保存領域、変更履歴を使うには、認証と共有データベースを別途追加する必要があります。
- Streamlit Community Cloudにはリソース制限があり、アクセスがないアプリは休止します。長期稼働や大量のPDF、厳密なアクセス管理が必要な場合は、専用サーバー等の配備先も検討してください。

## その他のローカル環境での起動

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
streamlit run streamlit_app.py
```
